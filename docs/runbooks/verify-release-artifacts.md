# Runbook — Verify release artifacts (cosign signature + SLSA provenance)

- **Audience**: ops / SRE / anyone installing a prebuilt binary
- **Related**: [upgrade-sentinel-binary](./upgrade-sentinel-binary.md), README "Installation" section

## When to use

Before trusting any prebuilt Sentinel binary or archive downloaded from GitHub
Releases — as part of an upgrade, a fresh install, or a supply-chain audit.
Two **independent** checks are available; use either or both.

| Check | Proves | Tool |
|---|---|---|
| Signature (cosign) | **Who** published — `checksums.txt` came from Sentinel's release workflow on a tag | `cosign` v3+ |
| Provenance (SLSA) | **How** it was built — from which source commit / workflow, untampered | `slsa-verifier` |

Neither replaces the plain `sha256sum -c checksums.txt --ignore-missing` check —
they layer assurance on top of it.

## 1. Verify the signature (cosign keyless)

`checksums.txt` is signed with cosign keyless (GitHub OIDC + sigstore
public-good Fulcio/Rekor). A bundle `checksums.txt.sigstore.json` ships beside
it. Needs `cosign` v3+ (`brew install cosign`) — no Go toolchain, no Sentinel
install.

```bash
BASE=https://github.com/denisakp/sentinel/releases/latest/download
curl -LO "$BASE/checksums.txt"
curl -LO "$BASE/checksums.txt.sigstore.json"

cosign verify-blob \
  --certificate-identity-regexp 'https://github.com/denisakp/sentinel/.github/workflows/release.yml@refs/tags/.*' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --bundle checksums.txt.sigstore.json \
  checksums.txt        # → "Verified OK"
```

Then match your archive against the now-trusted list:

```bash
sha256sum -c checksums.txt --ignore-missing
```

Fails closed: a tampered `checksums.txt`, or a signature from any other
identity/issuer, is rejected.

## 2. Verify build provenance (SLSA)

Each recent release ships a SLSA build-provenance attestation
(`multiple.intoto.jsonl`), generated by a process with its own identity —
independent of the job that built the binaries. Needs `slsa-verifier`
(`go install github.com/slsa-framework/slsa-verifier/v2/cli/slsa-verifier@latest`).

```bash
VERSION=<version>          # e.g. 1.4.0 (no leading "v")
OS=linux; ARCH=amd64
BASE=https://github.com/denisakp/sentinel/releases/latest/download

curl -LO "$BASE/sentinel-$VERSION-$OS-$ARCH.tar.gz"
curl -LO "$BASE/multiple.intoto.jsonl"

slsa-verifier verify-artifact "sentinel-$VERSION-$OS-$ARCH.tar.gz" \
  --provenance-path multiple.intoto.jsonl \
  --source-uri github.com/denisakp/sentinel \
  --source-tag "v$VERSION"
```

A tampered archive, or an attestation from an unexpected source repo/tag, is
rejected.

## Old releases (fail-open)

Releases published **before** each feature shipped carry no bundle / no
attestation:

- No `checksums.txt.sigstore.json` → use the checksum-only path (§1 tail).
- No `multiple.intoto.jsonl` → skip §2.

Verification is fail-**closed** only when the artifact is present: a missing
asset on an old release is expected; a *present but invalid* asset is a hard
failure.
