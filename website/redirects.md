# Redirect ledger

Once a page has been published it keeps its URL forever. The site is public from the first
increment, so URLs escape into bookmarks, search engines, and issue threads well before the content
is finished. If a later increment moves or renames a page, the original URL must redirect to the new
one rather than 404.

Every row below has exactly one matching entry in the `redirects` array of
`docusaurus.config.ts`. A change that adds one without the other is incomplete.

## Rules

- `From` is the path **as it was published**, including the `baseUrl` prefix in force at the time.
  Getting this wrong produces a redirect that never fires.
- Rows are **append-only**. Never delete one — the URL it protects may still be in someone's
  bookmarks years from now.
- Collapse chains: if A moved to B and B later moves to C, point A directly at C.
- `Reason` explains *why the page moved*. "Renamed" on its own is not a reason.

## Verification

Redirect stubs are generated by `npm run build` only — **never** by `npm start`. A redirect that
appears not to work in the dev server is not a bug. Check it against the production build.
